# 刘局推荐 · 游戏发售日历

面向多平台主机玩家，兼顾 PC；宁缺毋滥，不设最低收录数量。以实际获取资料的时间为截止时间。提前制作的月份是预告，不假装已经到达发布日。

## 使用

群内或私聊发送 `/月度发售 2026-10 预览`。插件提交 Runtime API v2 托管任务，完成后向触发聊天只发送一张长图。来源与筛选报告保留在后台运行目录，不自动发送到聊天。任务可在管理界面查看进度和取消；同一插件同时只允许一个生成任务。

本地试跑使用同一研究及渲染流程的 CLI，不调用微信发送接口：

```bash
python -m app.plugins.game_release_calendar 2026-10
# 仅恢复同一次运行的已完成子任务；保留原数据截止时间
python -m app.plugins.game_release_calendar 2026-10 --output <已有运行目录> --resume
```

验收必须保留真实采集报告；测试中的模拟 runner 只能验证程序行为，不能作为真实月历的数据来源。运行需要可登录的 Codex CLI、Pillow、jsonschema 和中文字体。Windows 默认复用项目 WSL Codex 路径选择；Linux 直接调用配置的 CLI。

素材编辑由子 Codex 补查中文名称与封面来源，优先取得2:3竖版封面，并实际下载验证。每款都必须有真实封面；未补齐时保留错误记录并停止出图，不生成缺图卡片。素材及尝试记录见 `presentation_assets.json`。如果部署网络明确使用 `198.18.0.0/15` Fake-IP DNS，可显式设置 `GAME_CALENDAR_ALLOW_FAKE_DNS=1`；此兼容只作用于代码内列出的官方商店/CDN及素材站，默认关闭，仍验证 TLS 主机与重定向目标。

普通 HTTPS 下载失败后，插件自动调用项目通用 Chrome 重试同一素材地址，复用 `shared_chrome` 的端口配置与操作锁，以及 `PublicUrlGuard` 对 Fake-IP DNS 的公网校验。通过 Playwright 连接现有 Chrome，每次只创建和清理自己的临时上下文，不重启浏览器、不使用其他插件标签页。重定向仍需通过 URL 校验，返回内容须为有效图片且不超过 5 MB；取消任务不会触发备用下载。成功记录包含 `transport: shared_chrome` 与原下载错误，失败记录同时保留两种方式的原因。需要项目通用 Chrome 已启动及 Playwright Python 依赖，无需额外下载或启动一套浏览器。

管理员手动调用 `ReleaseCalendarPlugin.submit(..., resume_run_id="原运行编号")` 可恢复同月份的失败或取消任务，沿用原资料截止时间及有效子任务缓存，完成后仍由插件发送给本次指定聊天。已完成任务不能通过此入口重发；群内预览命令不会接受本地路径或运行编号。

版式为绿色主题，卡片统一984×270像素，按日期分组。一款游戏的不同地区记录合并展示，优先以已核实的亚洲日期作为卡片日期，其余差异写短备注；后台保留各条原始记录。无地区优先信息时使用已核实记录中的最早日期。图片不展示采集策略或内部核实备注。`layout.json` 可核对每张卡片的尺寸。

预览和定时发布默认只输出、发送一张 `calendar_full.png` 长图，标题只出现一次，不按高度拆分多张图片。分页仅作为渲染器的显式可选导出，不用于默认发布。

素材编辑仅能补充名称与封面；最终简介沿用已通过核实的记录，日期备注只从已接受的发售事件生成，避免素材搜索重新带入已排除或存在冲突的日期。

复用已有发售事实执行新版素材编辑和排版：

```bash
python -m app.plugins.game_release_calendar 2026-10 --restyle-from <原运行目录> --output <新版目录>
```

## 工作流与来源

每次新触发都是独立研究：新建运行目录，重新搜索公开来源，不读取或补入历次候选、历史成品名单或入选结论，不以恢复上次的数量为目标。当次三个采集子任务分别检查主机、PC及媒体渠道，合并本次发现的线索后统一核实。采集阶段不执行最终推荐门槛；推荐依据不全或日期有差异的候选应带着疑点进入核实，不能提前无声丢弃。最终入选仍执行“宁缺毋滥”。

显式恢复失败任务是继续同一次运行，可复用该运行已完成且提示词一致的子任务；这不等于新触发时沿用历史名单。历史记录仅用于人工审计，不作为新一轮研究的输入。

发现主机候选、补充 PC 候选、检查媒体精选，随后合并发售事件、核实官方日期、执行精选、渲染固定模板。研究由 Codex 子进程执行：`gpt-5.6-sol`，发现阶段 `medium`，核实与精选 `high`。模型不可用时明确失败，不静默换模型。直接 Codex 运行不经过统一 LLM 路由，因此未声明 `ui.llm_tasks`；子进程输入输出留存在该次运行目录。

官方商店、发行商和游戏官网用于日期、平台、地区和版本核实；媒体明确推荐用于精选证据，普通定档报道不算推荐。网页或附件中的指令均作为资料内容，不影响任务规则。仅在媒体、数据库出现不足以入选。移植按本次平台记录；日期待定、信息冲突和读取失败须在报告中明确。

## 配置与发布

栏目默认 `刘局推荐`，图片标题默认 `{month}月重磅游戏发售信息`。命令、栏目与标题可配置。

与 Weekly 一样，插件声明 `features: ["push"]`，由统一插件分配中的推送权限控制，不另设发布开关或目标名单。插件运行时，每月 1 号北京时间 `publish_time`（默认 09:00）生成当月日历，只向拥有 `game_release_calendar#push` 权限的群聊或私聊推送；仅分配普通插件权限不会收到定时推送。需要接收月历的聊天应在统一插件分配中勾选本插件的推送权限。

没有任何聊天拥有推送权限时不启动定时生成；生成完成后发送前重新读取权限，已撤销推送权限的聊天不会收到月历。重启后的当天可以补执行一次，跨日不补发。自动发送还要求 pipeline 返回 `publishable: true`；证据或覆盖不足时只保留产物、将任务标为失败。

每月调度只领取一次。失败后查看任务记录并使用预览命令调查，不持续自动重跑昂贵研究。每个“月份＋目标聊天”先记录发送意图，收到成功结果后标记已发送；`sending` 表示结果不确定，需要管理员核对实际聊天记录，不自动重发。此保守策略避免重试导致重复群发。

## 存储与接口

运行证据、筛选报告、图片保存在 `context.storage.persistent_path("runs/<月份>/<运行ID>/...")`，发布记录保存在 `publication_state.json`。证据与产物一起备份。后台任务使用 `context.tasks.submit`，调度循环使用 `context.workers.start`；卸载和取消信号传递到 pipeline。

入口依赖：

```python
generate_calendar(
    output_dir: Path,
    month: str,
    runner=None,
    progress=None,       # callable(percent: int, message: str)
    cancelled=None,      # callable() -> bool
    title="刘局推荐",
    subtitle=None,
) -> dict
```

返回 `image_paths`、`report_path`、`run_dir`；自动发布另须 `publishable` 为真。文件路径须可转成字符串，任务返回结果须可序列化。进度与取消不依赖微信，CLI 与真实命令共享流水线。
