# 图片编辑

支持 `跟随默认 / Codex 内置 / API`，在插件默认设置或聊天中的插件设置选择。渠道在 **模型配置 → 图片生成** 管理，可勾选和排序。

内置模式使用**全局默认 Codex Profile** 的官方 ChatGPT 登录，在一次独立 `codex exec --ephemeral` 进程中完成图片编辑或生成。每次任务重新读取默认 Profile，继承其模型和认证，不使用聊天绑定的 Profile，也不复用聊天进程或历史。需要该 Profile 的 Codex 环境具有真实生图能力；失败后不转 API。

API 模式由宿主直接调用已勾选的生图渠道；所有允许渠道耗尽后，使用全局默认官方 Codex Profile 的内置生图补齐剩余图片。回退需要该 Profile 已登录且具有生图能力，内置失败即结束。渠道失败后依序尝试后续配置，成功即停止；批量请求保留成功图片，只补未完成数量。每个渠道使用自身超时，API 和内置回退共用 `processing_timeout` 总时限；取消、总超时和发送失败不触发回退。接口能力及配置继承规则见 [图片生成配置](../../../docs/IMAGE_GENERATION.md)。

- `P图 修改描述`：收集 1 张参考图后编辑。
- `P图2 合成描述`：收集 2 张参考图，一次传入同一个任务。
- `P图0 图片描述`：无需参考图，直接生图。
- `P图2 +3 合成描述`：使用 2 张参考图，目标生成 3 张；实际产生的完整中间版本也会发送。

保留引用图片、后续补充描述和收集超时流程。`target_images` 默认 1；`processing_timeout` 控制单次任务总时限，默认 300 秒。原生任务超时后由现有 Codex 客户端终止进程树，不自动重新发起生图。

两种模式的完整图片均在发送前登记到 Bot 共用资产索引，保存不可变快照、版本及实际交付状态。发送失败保留成品，后续可通过聊天中的图片资产工具查看、续改或直接重发，不重新调用生图接口。停机时未发送的已登记图片标为可恢复。

内置模式下，未配置默认 Profile、未完成登录或默认 Profile 使用 API Key 时，会报告错误。API 模式使用新的统一渠道配置，不恢复旧的 Gemini/APIQIK 或 R2 流程。图片保存在插件标准 generated 存储目录的 `images/<任务ID>/` 下，内置模式的交付副本位于其中的 `artifacts/`；发送后保留，避免微信尚未读完文件。

任务执行时实时读取 Codex 事件，并约每秒检查本次线程的生成目录和附件目录。图片大小与修改时间稳定、格式及解码检查通过后，按内容哈希保存独立副本并排队发送。微信发送不会阻塞进程输出读取；最终附件与已发送版本按哈希去重。所有完整版本均发送，不以 `+数量` 截断；损坏或尚未写完的图片会继续等待。

任务记录新增 `image_discovered`（含源文件修改时间与发现时间）、`image_send_started`、`image_sent`、`image_send_failed` 和工具事件类型记录。任务超时或失败时，已捕获的图片仍保留并完成发送队列。`generated_at` 取文件修改时间，是落盘时间的近似值。

生图完成后的文件查找、复制和发送由宿主完成，Codex 无需为交付图片执行额外命令。已成功发送至少一张图片后，后续进程超时只记后台日志；尚未发送任何图片时仍提示超时失败。任务记录保留真实的进程超时状态，不将超时改写为正常退出。

命令事件实时保存命令内容（最多 4096 字符）、退出码、状态，以及输出尾部和错误摘要（各最多 2048 字符），并遮蔽常见内联凭据。即使任务超时，也可从 `codex_item_observed` 事件查看已执行命令；这些诊断信息不会发送到微信群。
