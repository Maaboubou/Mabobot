# 翻译助手：每聊天配置与复用模板

2026-09-12。根据升级实施及后续需求更新，取代最初研究方案中的兼容运行设计。

其他插件接入这层能力时，使用 [每聊天插件配置开发指南](PLUGIN_CHAT_CONFIGURATION.md)；本文保留翻译业务、当前界面与一次性迁移说明。

## 使用方式

聊天详情 → 功能插件 → 翻译助手 → **本聊天设置**。

- 顶部只有一个作用范围开关：「跟随默认设置」或「本聊天单独设置」；开启后语言与提示词一次解锁，不再逐字段选择继承。
- 互译方式为显式分段按钮：双语选择两种语言，输出源语之外的一种；三语选择三种，输出另外两种。语言槽下方实时显示「原文为中文时，输出 English、Български」示例。
- 语言可从常用建议中选择，也可直接输入；支持上移、下移调整输出顺序；双语时移除按钮与模式按钮都有明确提示。
- 保存按修改字段生成差异覆盖：只改语言的聊天不会被冻结提示词，之后修改全局提示词仍会传递过来；字段旁的「恢复跟随默认」可单独清除该字段的覆盖。
- 「保存并生效」直接写入聊天策略并立即应用，不再需要回聊天页二次保存；聊天页的「保存更改」只负责其余聊天设置。
- 提示词默认收起，展开后可编辑并插入 `${language_names}`、`${language_count}`；「恢复内置模板」只填入内置文本，与「跟随默认」含义不同。
- 「查看最终提示词」不调用模型；「试译」调用现有模型 mapping，仅在页面显示结果，不发送到微信。
- 全局入口为插件页的「配置」，标题「翻译助手 · 默认设置」，对所有未单独设置的聊天生效。聊天修改不重载插件，下一次处理消息使用新配置；正在处理的消息完成于原配置快照。

## 可复用模板

模板入口位于提示词区，不占用独立区块：可将当前语言与提示词另存为命名模板，也可导入、覆盖所选、重命名或删除。覆盖与删除需要确认，重命名使用模板名称输入框。

模板包含完整语言组合、顺序和提示词，不包含聊天授权、监听、@条件、账号凭据或模型连接。

**导入采用复制语义。** 配置复制到当前聊天编辑器，并自动切换到「本聊天单独设置」，成为可继续编辑的独立配置。覆盖或删除模板不影响之前导入的聊天，也不会隐式保存当前聊天。

模板按插件隔离、名称唯一；编辑和删除使用版本比较，冲突返回 409。

## 配置数据与协议

新增 `chat_plugin_configs`：

- `(user_id, plugin_name)` 唯一，关联稳定的数据库聊天 ID。
- `schema_version` 表示数据格式，`overrides_json` 只存显式覆盖字段。
- 关闭或重新保存授权不删除配置；删除聊天时由 ORM 关系级联删除。
- 聊天设置并入原有 `policy_version`，使用数据库条件 UPDATE 实现并发比较，而非依赖 SQLite 不支持的行锁。

新增 `plugin_config_templates`：

- `(plugin_name, name)` 唯一，保存完整 `config_json` 快照。
- 独立 `version` 用于模板更新、删除的冲突判断；不与聊天建立动态引用。
- 两张表均在正常数据库初始化时创建，进入主数据库的 SQLite 备份。

继承：内置默认 → 插件全局配置 → 聊天覆盖。数组整体替换，不合并语言条目。数量直接由语言数组长度决定，不单独保存双语／三语模式。

```json
{
  "languages": ["中文", "保加利亚语", "英文"],
  "prompt_template": "参与语言：${language_names}。保留型号、参数和原文语气。"
}
```

语言采用可读名称存储，常用代码和别名会规范化（如 en／English／英语 → 英文）。可输入自定义名称；同义自定义名称不可能只靠格式校验完全识别，翻译质量依赖实际模型。

只有 `config_schema` 声明 `scope: "global_and_chat"` 且非敏感的字段允许聊天覆盖。其余旧插件继续使用原全局设置。`PluginChatConfigService` 负责范围、类型、完整配置校验和来源计算；翻译插件补充语言与模板业务校验。

## 接口

- `GET /api/chats/{id}/policy`：返回 `plugin_configs`，含 `overrides`、`defaults`、`effective`、`sources` 和全局默认内容指纹。
- `PATCH /api/chats/{id}/policy`：插件配置、授权与其他聊天设置在同一事务提交。
- `GET /api/capabilities/settings/{plugin}?user_id={id}`：返回本聊天字段及其有效值；不带参数时为全局设置。
- `POST /api/capabilities/translation-preview`：提示词编译或模型试译，接受草稿配置，不保存、不发送微信消息。
- `GET /api/capabilities/config-templates/{plugin}`：列出模板。
- `POST /api/capabilities/config-templates/{plugin}`：创建模板；带 `template_id`、`expected_version` 时更新，包括改名。
- `DELETE /api/capabilities/config-templates/{plugin}`：请求体指定 `template_id`、`expected_version`。

聊天 PATCH 示例：

```json
{
  "expected_version": 16,
  "plugin_configs": {
    "builtin_translation": {
      "set": {"languages": ["中文", "日文"]},
      "reset_fields": ["prompt_template"]
    }
  }
}
```

省略字段表示不修改；空对象不修改；`reset_fields` 清除指定覆盖，`reset_all: true` 清除全部覆盖，且不能同时设置字段。过期聊天版本返回 409，非法配置返回 422。无覆盖的聊天正常继承；未知聊天或损坏配置不会借用其他聊天规则。

## 翻译运行时

EventBus 完成聊天身份和授权判断后注入可信 `chat_id`。Runtime API v2 增加 `context.config.resolve(chat_id=...)`，每次使用独立数据库会话读取聊天配置及磁盘全局默认，避免 Web／监听进程缓存不一致。

翻译服务接收本次配置参数，不修改共享提示词。正常路径一次模型调用识别源语言并翻译，继续使用 `builtin_translation / translate` 统一模型 mapping。

可编辑模板支持 `${language_names}` 和 `${language_count}`，未知变量拒绝保存，普通美元金额不被当变量。程序追加本次语言名单和 JSON 结果协议；原文单独放入 user 消息。

程序校验源语言、译文语言集合、数量、重复及空内容，然后按配置顺序使用目标语言的原生名称生成标签（如 English、Български、日本語）。常用语言名称由程序映射，自定义语言由模型提供并校验 native_name。错误格式最多额外纠正一次，仍失败则不发送。校验只能保证结构和声明一致，不能证明翻译语义或实际语种一定正确。

- 混入品牌和型号时，按主要自然语言判断源语。
- 配置外语种／无法判断主语种返回跳过状态。
- 纯数字、URL、标点和纯表情跳过；数字不再被误判成 emoji。
- 引用消息仅翻译新增文字。
- 微信表情标记（包括 [喜极而泣]）先用逐次唯一占位符保护，每段译文校验数量和顺序后恢复原标记，避免被翻译成表情说明。
- 仅清除模型额外生成在末尾的 HTML 空格实体，保留原文明确包含的实体和正文中的代码。
- 直接保留结构化译文正文，不再使用会删除型号下划线的 Markdown 清理正则。

## 安装与升级

公开版自 v3.4.0 起包含翻译助手。先在模型配置中为 `builtin_translation / translate` 分配模型，再到聊天页授权启用。

首次启动使用插件声明的通用语言与提示词默认值。若曾自行安装旧版本，升级前保存旧提示词，在新的全局默认或聊天设置中重新录入；旧 `prompt_translate` 不会自动迁移。标准升级不修改聊天授权，也不发送微信消息。

更新平台 Python 代码后重启 Bot 与 Web 服务，新表在正常数据库初始化时创建；之后聊天设置保存即生效，无需再次重启。
