# 存储空间管理

入口：**系统 → 存储空间**（`/system/storage`）。后端更新后需重启 Web 服务。

- **扫描空间**：后台遍历项目目录，每个文件只计入一个分类。展示文件总大小、所在磁盘可用空间、分类占用、主要目录及每类最大的 20 个文件。符号链接不跟随；无法读取的路径会提示统计不完整。文件大小与磁盘实际分配空间可能不同。
- **清理缓存**：选择保留 7、30、90 或 180 天，点击预览。只包含 `tmp/plugins` 和 `data/plugins/<插件>/cache` 中超过保留天数未修改的文件。预览展示总数、总大小及最大的 100 项。
- **移入回收区**：确认后仅移动该次预览的文件；新增、消失或修改后的文件不会被误纳入。预览有效期为 30 分钟，使用一次后失效，服务重启后需要重新预览。
- **回收区**：每批文件都有持久化清单。可恢复到原位置，同名新文件不会被覆盖；也可确认永久删除。移入回收区不释放空间，永久删除才释放。失败项会保留并提示。
- **备份**：通过“管理备份”进入现有备份页，使用已有的下载、校验和删除操作。

聊天附件、生成内容、聊天档案与数据库、模型、插件机器配置和运行环境只做统计，不提供批量删除。当前页面不自动清理、不分析图片内容重复、不删除聊天索引引用；本次开发没有清理真实业务文件。

扫描和清理通过后台任务执行，同一时间仅允许一个存储任务。页面重进后会接续观察运行中的任务；任务结果写入操作记录。清理、恢复或删除后旧统计会失效，需要重新扫描。

接口位于 `/api/operations/storage`：读取概览；`POST /scan` 后台扫描；`POST /cleanup-preview` 生成预览；`POST /cleanup` 使用 `preview_id` 移入回收区；`POST /trash/{batch_id}/restore` 或 `/purge` 操作回收批次。修改接口均返回后台任务，执行结果通过现有操作查询接口获取。
