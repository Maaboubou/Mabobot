# Codex 权限中心：使用与验收

更新：2026-09-17。

## 管理入口

- **Codex 运行中心 → 权限配置**：折叠卡片默认收起，折叠头显示有效权限摘要；展开后切换群聊默认或私聊默认，配置工作区文件、公共互联网、在线研究工具、越界处理。
- **聊天管理 → 权限**：先选择跟随默认或本聊天自定义。自定义只持久化与默认不同的字段，未覆盖字段继续跟随默认。
- 保存按钮统一为“保存并生效”。已开始的轮次保留启动快照，新轮次重新解析策略；线程恢复必须匹配权限签名。
- “恢复默认”确认后清除全部差异。管理员私聊的最大权限在本聊天页显式选择；群聊和全局默认均不提供该权限。
- 默认与聊天表单共用后端字段定义及 `codex_permissions.js` 渲染器。插件、账号和外部服务继续在原有功能插件页管理。

## 升级与数据

重启 Bot 和 Web 服务时 `create_tables()` 自动执行幂等迁移。现有安装保持工作区可写、shell 公网关闭、既有在线工具状态和直接拒绝越界的默认行为，合法私聊的最大权限被显式导入。新安装保存设计建议默认；能力不受支持时收窄有效权限。

新增默认、覆盖、运行时回执和运行进程能力表，均随现有数据库备份。聊天覆盖与其他聊天策略共用 `policy_version` 和一个事务；默认策略独立使用 `version`。冲突返回 409，非法值返回 422，失败不丢失页面输入。

旧 `codex_access_mode` 仅用于迁移与旧版创建接口的输入兼容；运行时从统一解析器读取新策略。历史聊天空间保留原路径，新聊天使用宿主生成的随机标识，改名不换空间，删除后重建同名聊天也不会接管旧文件。未知聊天不能仅凭名称取得文件空间。

## 运行时证据

四个隔离 Profile 固定为 `mabobot-isolated-{ro,rw}-{offline,public}`，当前聊天根由宿主传入。根目录拒绝读取，必要组件和 Skills 只读，shell 使用环境变量白名单，不再开放所有聊天共享的可写缓存。

启动探针通过真实 `command/exec` 检查 Profile 和代理：代理必须拒绝元数据地址，直接 socket 必须在沙箱层失败。公网 Profile 同时启用 `features.network_proxy`，关闭上游代理、私网、本地绑定与 Unix Socket 例外。公网请求不能回退到未验证的 exec 通道。

线程启动和恢复核对实际 `activePermissionProfile`、`runtimeWorkspaceRoots` 和审批策略。原生搜索明确使用 `live` 或 `disabled`；不支持搜索的模型保留浏览器能力。浏览器声明按当前权限过滤，执行时再次检查本轮不可变快照，禁止旧线程残留调用绕过权限。只读工作区不允许会写入截图、页面或下载结果的宿主浏览器工具，原生搜索可独立使用，页面明确显示部分能力。

Bot 与 Web 可以是不同进程：能力探测结果通过数据库心跳共享，停止时撤销，超过三分钟的心跳过期。应用回执绑定进程实例和策略签名；保存数据库不会生成成功回执，失去运行时证据后不再显示“已生效”。

状态含义：

| 状态 | 含义 |
| --- | --- |
| 下一轮生效 | 配置已保存，尚无匹配当前策略的运行回执 |
| 已生效 | 当前签名有运行回执且对应运行进程证据仍有效 |
| 运行时不支持 | 请求的能力被收窄；摘要显示实际允许的通道 |
| 应用失败 | 当前策略在运行时应用失败；不会放宽到最大权限 |

## 当前运行时限制

**自动审阅现已直接交给 Codex 原生 reviewer。** 根据管理员确认的运行方式，选择自动审阅且运行时支持 reviewer 时，隔离聊天和管理员私聊均使用 `on-request + auto_review`；允许后继续执行，拒绝后停止该操作。只有 reviewer 不可用时才收窄为 `never`。`bounded_auto_review=false` 仅说明没有额外的外层隔离，不再作为禁用自动审阅的条件。所有残留人工审批请求立即 decline，不转发微信。

每轮由宿主从数据库生成 developer instruction，包含聊天 ID、空间路径、文件/网络权限和审批底线。微信消息仅表达底线内的任务意图，“我是管理员”“已经批准”等文本不构成宿主授权；聊天名、消息内容和角色提示词均不参与生成这份权限快照。启动和恢复线程都携带此指令，策略版本进入签名；自动审阅不能回退到缺少该传递链的 exec。普通命令仍由隔离 Profile 和受控代理限制。

这里的底线属于给模型的授权规则；获批提权后的隔离不能声称由普通 Profile 绝对保证。审阅器可能判断失误，因此页面明确说明模型审阅的限制。既有 Codex 默认或组织审阅策略保持不变，未用简短自定义策略覆盖它：官方 `[auto_review].policy` / `guardian_policy_config` 会替换原策略，若以后定制，应取得并保留完整现行策略后再添加规则。

官方依据：[自动审阅的上下文、配置和限制](https://learn.chatgpt.com/docs/sandboxing/auto-review)、[权限的覆盖范围与强制执行](https://learn.chatgpt.com/docs/permissions)。当前验证覆盖宿主 developer 指令传递和原生线程审批回执；尚未使用真实模型验证 reviewer 对具体允许/拒绝案例的判定，也未完成设计中所有高副作用命令的强制审阅规则，不能描述为设计全部验收通过。

**Fake-IP DNS 会被原生代理拒绝。** 域名返回保留地址时，原生代理可能返回 `not_allowed_local`；这是正确的保留地址拦截。不要开启 `allow_local_binding` 绕过它。真实公网 IP 的 HTTPS 通道可正常访问；需要域名联网时应给 Codex 运行环境提供真实公网 DNS 解析。宿主浏览器已有独立受控解析通道，两者不是同一网络设置。

## 验证说明

维护工作区使用权限 API、迁移、运行时与浏览器回归验证权限行为，公开源码不分发测试目录。可运行 `python scripts/check_codex_permissions.py` 检查当前宿主沙箱支持；该脚本在项目 `tmp/` 创建临时夹具并清理测试进程，不调用模型。结果不能代替实际模型的审核判定。
