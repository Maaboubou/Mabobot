# Mabobot v3.12.0：统一 AI 中心与 OpenCode 接入

本次发布将 Codex 与 OpenCode 纳入同一套 Profile、任务与模型管理流程，支持独立部署、Windows / WSL 安装，以及可恢复的图片和插件任务。

## 新功能

- **AI 运行中心**：统一查看两种引擎的 Profile、登录状态、可用模型、原生会话、任务、上下文和用量；支持独立设备授权及模型能力验证。
- **可选 OpenCode 安装**：Windows 启动器配置向导和“工具与更新”提供安装及失败重试；使用 WSL 中锁定版本的受管进程。Linux 可直接部署。支持 `codex`、`opencode`、`codex,opencode` 三种安装组合。
- **共享模型与任务路由**：支持订阅模型卡、主备候选、逐聊天引擎及逐任务直接生成 / 工具模式。旧 Codex 卡和专用接口保留原行为，新路由默认关闭，需验证并手动启用。
- **任务与交付恢复**：持久记录任务、取消、会话、权限、生成产物和交付状态。已派发请求断线后保持未知，管理员核对后继续，不自动重跑。
- **图片与插件**：图片编辑、摘要脑图和 Weekly 接入统一执行契约；图片操作独立登记，Weekly 保存页计划、已完成图片及 PDF，恢复时复用已有文件。
- **跨引擎终端**：按引擎选择 Profile，保留会话重连；OpenCode 使用独立环境和账号。
- **备份与迁移**：SQLite 在线一致快照包含已提交 WAL；支持引擎配置迁移、恢复后暂停派发和保留任务账本的代码回退。
- 改进微信引用表情读取、消息上下文恢复、任务回复与启动器配置向导。

## 升级与启用

1. 升级前备份配置和数据库；更新代码、安装项目依赖并完整重启 Web / 微信服务，刷新控制台和启动器。
2. 继续使用 Codex 的用户可保留现有配置；仅部署 Codex 时设置 `MABOBOT_ENABLED_ENGINES=codex`。
3. 使用 OpenCode 时，先通过向导或工具页面显式安装，再创建独立 Profile、登录并验证所选模型能力。安装不会自动切换已有聊天和模型卡，也不会复制 Codex 登录凭据。
4. 逐项配置主备路由及任务模式后，再在测试聊天启用新路由。图片入口仍需分别配置其原生 Codex 或 API 渠道。
5. 使用当前版本工具恢复备份；恢复后先核对账号、权限、未决生成及交付，再解除暂停。OpenCode 首版仅迁移配置，换机器需重新安装并登录。

OpenCode 固定使用 `2.3.0+mabobot.p0.1`；不自动安装上游最新版本。普通聊天的宿主工具继续受授权与隔离限制，未验证能力保持不可用。用量或额度无可靠来源时显示未知。微信自动化仍需 Windows 交互桌面及已登录的客户端。

备份压缩格式仍为 v2；包含新引擎表的备份标记为 `mabowx-v2-engines-v1`，旧版程序会拒绝恢复该代际。代码回退须先停止接单并处理在途和未知任务，不得用旧数据库覆盖新账本。
