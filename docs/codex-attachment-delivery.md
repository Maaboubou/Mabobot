# Codex 聊天附件交付

App Server 普通聊天在原有最终回复中携带 `_mabobot_reply` 和
`_mabobot_files`，通过 `outputSchema` 约束格式。宿主解包后，角色原有的
JSON/文字回复协议保持一致；附件路径不会进入微信文字消息。

拟人分条回复也使用同一协议：将角色原来的 `status`、`messages` schema
完整嵌入 `_mabobot_reply`，模型直接返回嵌套 JSON 对象。宿主提取后序列化成
原来的角色 JSON，再交给原有终态校验和分条发送流程，保留状态枚举、消息条数
限制及顺序。普通文字回复的 `_mabobot_reply` 仍为字符串。

- `_mabobot_files` 按顺序选择最终文件；空数组明确表示没有附件。
- 原生生图路径只接受本次请求的成功 `imageGeneration` 完成事件记录。
  模型不能凭空提交其他会话的缓存路径。宿主复制选中的图片到本次
  `outputs/delivery-<随机标识>/`，保留群聊隔离，不开放全局生成目录。
- 文档、表格、演示文稿、音视频等最终文件仍写入本次 `outputs`，并在清单中
  使用相对路径。参考素材和中间产物不要放入清单。
- 路径、文件类型、图片结构、非空文件及内容哈希由宿主校验；任一选中文件
  失败则整个交付失败，删除本次导入的部分文件，不发送模型的成功回复。
- 生图完成不等于需要发送：PPT 插图、废弃版本可以不出现在最终清单中。
- 不新增模型调用或附件提交工具；多图导入后统一计算哈希，按内容去重。
  `artifact_delivery_validated` 记录选中文件数、生成数、附件数和处理耗时。

兼容范围：只有显式 `codex_text_only` 跳过附件协议；调用方自带的
`output_schema` 会嵌入交付协议，不会再绕过附件清单。
旧回复格式采用兼容回收：已有 outputs 优先，否则依据本轮成功生图事件回收，
不使用用户文字关键词判断。该兼容分支无法像清单一样精确区分最终版本，
新的普通聊天应使用清单。独立 Codex CLI/图片流接口不在本次协议变更范围内。

回归测试覆盖：粤语修改追问的一轮交付、最终版本选择、多图顺序、文档排除
中间图片、角色 JSON 解包、其他会话路径/目录穿越/符号链接拒绝、损坏或缺失
文件、失败生图事件、部分导入清理，以及原有 App Server 和权限测试。
拟人分条角色另覆盖：自带 schema 的一轮交付、显式空清单排除中间图片、
附件缺失阻止成功返回，以及原 schema 不被修改。
