# 图片生成

入口：**模型配置 → 图片生成**（`/ai/images`）。升级默认仍为 Codex 内置模式。

## 渠道与顺序

- 内置模式使用现有 Codex 生图能力，失败结束，不转 API。
- API 模式仅尝试已勾选的渠道，依列表顺序执行，成功即停止。全部允许渠道耗尽后自动尝试 Codex 内置生图，只补齐尚未完成的图片；内置失败即结束，不再转 API。取消、总时限已到、参数校验及交付失败不会触发回退。没有启用的 API 渠道时也尝试内置。
- 新配置默认不启用。取消勾选保留配置；拖动或上下箭头调整顺序。
- 配置可以独立填写连接信息，也可以引用 API 类型的 Codex Profile。引用只复用地址和密钥，生图模型与参数独立。
- “测试生图”只调用选中的配置生成一张图，也允许测试尚未启用的配置，不使用备用队列。测试图片临时保存并返回预览。
- 修改配置作用于新任务。每次任务使用开始时捕获的模式、渠道与顺序。
- 新建和编辑配置使用模型下拉框。填写密钥或选择 API Profile 后，自动请求当前连接的 `/models`；刷新按钮可重新获取。官方列表按图像模型名称和停用日期筛选，Responses 主模型按已知工具支持范围筛选。该接口不提供完整能力元数据，列表可见性不等于所有生图操作都已授权。
- 未配置连接或获取失败时使用明确标注的内置候选列表。第三方额外返回的模型在“其他模型”中选择，也可以选“手动输入”。发现接口只读取目录，不创建图片、不保存未提交的密钥。

## 配置层级

Bot：聊天设置 → 全局默认。

插件：该聊天的插件设置 → 插件默认 → 全局默认。插件的生图设置与 Bot 的聊天生图设置独立。

局部设置中的“跟随默认”继承上层模式；默认队列继承上层渠道顺序。勾选或排序后成为局部队列，“恢复默认队列”重新继承。显式空队列表示无可用渠道，全局停用的配置始终不会参与正常任务。

## 聊天请求临时切换

在“模型配置 → 图片生成”开启 **允许聊天请求临时切换生图模式** 后，Bot 可响应“这次用 API 生图”或“这次用 Codex 内置生成”。开关默认关闭；聊天设置中的“本次模式切换”可跟随全局、单独允许或禁止。未指定时始终使用该聊天的默认模式，上一任务的临时选择不会继承。

Bot 在开始生图前调用本地 `images.select_mode`，引用当前用户的明确要求。宿主检查开关、当前任务权限及 API 渠道是否可用，再记录本任务的选择。切换不修改全局或聊天配置，不增加一次模型调用，也不产生生图 API 请求；只增加少量工具说明及一次本地工具往返。真正生图时才调用所选方式。API 仍使用后台允许的渠道队列、质量和复杂度。

开启切换时会同时提供内置生图和 API 工具，由任务规则指定默认及所选方式；API 工具由宿主检查本任务已选择 API。API 模式始终保留内置工具以执行宿主授权的单向回退；开关只控制用户主动选择模式。切换权限或默认模式变化会更新会话工具签名；需要宿主工具的任务不能降级到 `codex exec`。

仅要求 GIF、参考图编辑或接口报错不构成切换依据；已开始生图的任务拒绝切换，API 队列耗尽后的自动回退由宿主单独授权，不通过 select_mode。缺少可用 API 渠道时会附带原因并尝试内置。最近 API 调用显示实际方式、默认模式及是否由用户本次指定，原始要求不写入该记录。原有任务工具记录仍可查看切换步骤和内置生图调用。

此开关适用于 Bot 的聊天任务。P图和 Weekly 的固定流程继续按各自配置选择生成阶段，不接受提示词临时切换。

## API 能力

支持 OpenAI Images 生成与编辑，以及 Responses 生图工具。Responses 的“主模型”负责工具调用，“生图模型”指定工具使用的图像模型。

官方参数按模型能力校验：尺寸、质量、复杂度、透明背景、格式、动画帧数／时长、压缩、数量、输入保真度、过滤级别、流式接收和部分图片帧数。可用模型目录基于 2026-11-05 的官方文档，模型 ID 保留手动输入能力。新增配置默认推荐 GPT Image 2.6 Flare，已有配置不自动换模型。

Images 编辑支持 JSON 和 Multipart 两种传输，兼容只接受 Multipart 的第三方服务。宿主支持多张参考图、PNG 蒙版，以及 GPT Image 2.5 / 2.6 的标注输入。GIF/BMP 等参考图会先转换为 PNG；GIF 参考图只使用首帧，不是动画编辑。

### GPT Image 2.6

- 模型：`gpt-image-2.6-flare`、`gpt-image-2.6-sunburst`，支持 `xhigh` / `max` 质量。Images 配置可选 `complexity=low/medium/high`，省略时官方默认为 high。
- GIF：Images 文生图使用 `output_format=gif`；`frame_count` 为 2–64（默认 9），`frame_duration_ms` 为 20–2000（默认 200，接口按 10ms 取整）。尺寸指每一帧，支持 `auto` 或 16 倍数的正宽高，例如 `512x512`。官方未公开完整的总像素预算，超限需减少帧数、尺寸或数量。
- SVG：Images 文生图使用 `output_format=svg`，每次 1 张，作为矢量文件交付。只接受静态 SVG，拒绝脚本、外部资源和嵌入位图，不作为后续编辑参考图。
- 直接输出 GIF / SVG 的接口不支持参考图编辑、Responses、流式、预览帧、输出压缩或 `prompt_rewriter`。这些是单次接口限制，不限制 Codex 使用静态帧完成多步动画制作。不会静默丢弃参考图或把静态图当作成品动图交付。
- Bot 可按用户要求指定 GIF/SVG 格式和动画参数，质量、复杂度由渠道配置控制。切换格式时清理原格式不适用的默认参数；GIF 与静态图之间切换时，无任务尺寸就用 auto。原始 GIF 字节完整保存、预览和交付；调用记录包含实际帧数和总时长。本地验证逐帧解码，限制为 64 帧、每帧 4000 万像素、总计 1.28 亿解码像素，独立于官方接口限制。

设置示例：选择 2.6 模型与 Images 接口，质量保持 max，格式选 GIF，尺寸 auto、9 帧、每帧 200ms；提示词描述主体、动作和循环。P图需要参考图，应使用 PNG/JPEG/WebP 配置；Weekly 自动请求静态 PNG，以生成 PDF 页面。

### 多帧合成动图

Bot 可通过 `images.capabilities` 查询本次任务的渠道和直接 GIF 能力。对 2.5 等没有直接 GIF 输出的模型，或带参考图的动画任务，Codex 仍可保留参考图并规划动作，调用 `images.generate` 生成连贯的 PNG 静态帧或帧网格，再用本地工具切分、统一尺寸，最后通过 `images.compose_gif` 合成动图。每次生图沿用配置的 API 渠道及质量；允许渠道耗尽时，宿主授权内置生图补齐剩余素材。多帧流程可能包含多次生图，仍受任务总时限和原有调用规则约束。

`images.compose_gif` 只编码已经存在的静态帧，不调用模型。支持 2–64 帧、统一帧时长和循环次数，帧路径沿用当前任务／当前聊天的文件访问校验。交付列表只包含最终 GIF。若误用不支持的直接 GIF 请求，宿主会返回 `requires_frame_composition`，让 Codex 继续制作静态帧；真正的网络或服务端错误不会被伪装成能力限制而触发重复付费调用。

微信交付继续遵循现有审核规则：GIF 逐帧审核后发送原文件，仍受 `max_visuals`（当前默认 60 帧）等限制。SVG 需管理员文件许可清单包含 `.svg`，通过静态内容校验和渲染审核后才发送；升级不会自动扩大现有许可清单。

第三方按 OpenAI 兼容协议接入，可填写自定义模型名、请求头和额外 JSON 参数。额外参数不能覆盖任务内容、模型或标准参数。此版本不处理完全不同的请求协议及异步任务轮询接口。

### 第三方 Images 接口

选择“兼容接口”和 Images，API 地址填写接口前缀，程序再追加 `/images/generations` 或 `/images/edits`。例如：

| 服务 | API 地址 | 文生图路径 |
| --- | --- | --- |
| 快跑图像 v2 | `https://image.kuaipao.pro/v2` | `/v2/images/generations` |
| 使用 `https://ai.centos.hk/v1` 的兼容服务 | `https://ai.centos.hk/v1` | `/v1/images/generations` |

兼容渠道的可选参数可留为“服务商默认／不发送”。不要把官方模型的全部扩展参数直接套到第三方；模型名称、质量值、尺寸、动图、编辑及 Responses 能力需分别以该服务的实际支持范围为准。兼容 Images 额外允许 `standard`／`hd` 质量，但不代表每个模型都接受。已有配置的显式参数会保留，需要时手动改为不发送。

快跑的 `size` 与 `aspect_ratio`／`resolution` 不能同时发送；使用额外参数指定比例和档位时，将尺寸留空。快跑 JSON 编辑使用 `image` 字段，与当前 JSON 编辑格式不同，应选择 Multipart 编辑传输，其文档也支持当前发送的 `image[]`。

两类接口的标准结果 `data[].url` 和 `data[].b64_json` 都可接收。兼容服务也可以在 `data[].url` 中返回 `data:image/png;base64,...` 等内嵌图片数据，宿主会直接解码，并沿用 50 MiB 大小、图片解码、动图和 SVG 内容校验，不进行 DNS 或网络下载。普通 HTTP(S) URL 返回仍需另外下载文件；若图片存储地址无法通过公网校验或不能连接，可在“额外参数”设置 `{"response_format":"b64_json"}`，由支持该选项的渠道直接返回图片数据。图片下载不携带生图 API Key，也不会放开内网地址访问。

接口已返回图片链接后，公网地址校验、DNS 或下载失败会单独显示为“图片下载”失败，记录安全错误分类、脱敏链接、链接长度及具体拒绝原因；链接路径、查询参数和片段全部隐藏，不保存完整签名链接或原始异常。此类失败不切换渠道重新生图，也不触发 Codex 内置生图回退；已经保存的部分图片仍保留。旧版泛化错误记录无法追溯具体下载失败原因。

参考：[快跑文生图](https://kuaipao.apifox.cn/521245164e0)、[快跑图生图](https://kuaipao.apifox.cn/521245165e0)、[快跑参数规则](https://kuaipao.apifox.cn/521245157e0)。

文档：[官方生图指南](https://developers.openai.com/api/docs/guides/image-generation)、[Images 生成](https://developers.openai.com/api/reference/resources/images/methods/generate)、[Images 编辑](https://developers.openai.com/api/reference/resources/images/methods/edit)。

## 运行与交付

### 微信引用表情

引用“动画表情”与引用图片使用相同的按需读取和编辑入口，原始 GIF 完整保存在 `mabowx文件下载/emoticons/`。读取时从该消息所属微信进程的内存中只读解析引用资源标识，使用微信提供的素材地址取回原文件，并核验资源 MD5 和当前引用缩略图；不会按“最近修改的缓存文件”选择图片，也不会记录原始 XML、下载凭据或账户密钥。重复资源复用已校验的本地文件。

这是微信 4.x 缺少表情下载 UI 时的兼容路径，引用必须在当前聊天中唯一可见。引用原始数据不在内存中、存在无法区分的相同引用、素材不可用或缩略图核验失败时，会明确失败。微信昵称、联系人备注和引用 XML 的显示名可能不同，显示名不用于排除候选；同标题的不同引用身份仍一律拒绝猜测。

开启聊天附件记录时，引用表情也有 `attachment_id`，后续可通过历史工具读取或继续编辑。历史查看允许 GIF、APNG、WebP 动图，返回原始字节及动画帧数，不主动转为静态图。实际模型通道是否接受动画输入仍由该通道决定；Images API 编辑的既有 GIF 首帧适配规则不变，元数据会注明转换，不能据此声称修改了整段动画。

Bot 在 API 模式下使用宿主的 `images.generate` 工具；内置工具保持可用，但仅在宿主返回 `native_fallback_required` 后自动使用。该结果包含缺少数量、原始描述、已校验的参考图及蒙版/标注路径；已有文件保留，后续 API 调用被阻止。模式变化会刷新会话工具签名。需要此工具的请求不会降级到没有宿主工具的 `codex exec`；第三方聊天 Profile 也使用同一宿主工具。

聊天生图质量和复杂度采用所选渠道的配置，Bot 不能自行覆盖；旧会话传入的质量参数也会被宿主忽略。尺寸仍可按任务要求指定。切换备用渠道时使用该渠道自己的质量配置。

两种模式共用图片资产和版本索引。每个完整生成结果保存一份不可变快照和稳定 `asset_id`，记录父图、版本、批次序号、实际格式/尺寸/透明度、原图来源及交付状态。最终选择的图片（含本地裁剪、合成或原地修改后的成品）再次登记；中间素材不会自动当作最终成品发送。索引不再截断为最近 32 张，查询支持分页。历史旧记录仅在原路径哈希仍匹配时迁移，无法确认旧图发送状态时标为未知。

`images.recent` 默认列出最终成品、可恢复的中断结果和旧版迁移候选；可显式查询中间素材。若进程突然退出，来不及记录中断状态，助手可通过 `include_intermediate=true` 查找已落盘素材，核对任务并看图后再继续或交付。助手按资产 ID、批次序号和交付状态选择图片，不能把最新生成的帧误当用户收到的最后一张图。`images.read` 返回受限预览；`images.export` 将已授权快照复制到本轮输入目录供内置生图/本地处理，或复制到输出目录供直接重发。两种模式均可使用这些本地工具，导出和重发不产生生图 API 调用。切换模式、线程轮换或重启后，已登记图片仍按聊天隔离并校验快照哈希，不扩大文件系统权限。

API 编辑可通过 `reference_asset_ids` 选择已生成图片版本；蒙版和标注分别支持路径、`mask_asset_id` / `markup_asset_id`、`mask_attachment_id` / `markup_attachment_id`。已登记首张参考图的格式、透明背景和受渠道支持的尺寸默认延续，本轮显式参数优先；质量和复杂度仍由渠道控制。生成结果带图片预览及有效参数，供助手核对文字、主体和局部修改；预览不替代原始编辑/交付文件。

继续使用前几轮用户发送的原图时，助手可将历史记录中的 `attachment_id` 作为 `images.generate.reference_attachment_ids` 传入。宿主复用历史会话的当前聊天归属、删除状态、文件校验、读取预算和审计，不依赖上一轮临时文件路径，也不向模型开放归档目录。编辑输入与当轮图片使用同一 50 MiB 限额和规范化规则，GIF 使用首帧、BMP 转 PNG，PNG 蒙版保留透明通道；普通历史看图接口仍使用自身预览限制。历史原图仍在且可读取时，无需用户重发；历史读取未启用、文件已清理或消息已删除时会明确失败。路径、历史 ID 和资产 ID 合计最多 16 张参考图。

P图保留收图与描述流程，API 模式直接调用图片服务。`processing_timeout` 对两种模式均为任务总时限；API 还受各渠道超时约束。P图两种模式在发送前登记成品，按实际发送结果更新状态，失败的图片仍可由 Bot 按资产 ID 恢复。Weekly 保留策划、分页、PDF 生成和发送流程，仅切换逐页生成阶段，并受整批超时约束。API 队列耗尽后，P图仅补齐缺少数量，Weekly 仅生成未完成页面，均沿用剩余总时限；内置不可用或失败时结束并保留已有结果。

部分成功后保留已有文件，仅向后续渠道请求剩余数量。完整流式结果参与交付，预览帧不会发送。图片按内容去重并校验解码。取消、总时限结束或调用失败时保留已完成文件和尝试记录；完整图片落盘后立即登记，原生成功生图事件也由宿主保存快照。未正常完成的任务把这些图片标为可恢复，不自动发送中间版本；下一轮可以查看、继续编辑或直接导出重发。取消任务后不继续尝试渠道；微信发送失败不会重新生成。取消本地等待不代表上游已撤销生成或计费。

超时不代表服务端一定未完成，调用记录会标记结果未知；宿主仍按配置尝试下一渠道，迟到结果不会重复交付。所有渠道还受所属 Bot／Weekly 任务总时限约束。

最近 100 次 API 调用保留执行结果、渠道、模型、接口、生成／编辑类型、任务覆盖后的标准参数、实际图片尺寸、耗时及每次尝试的错误类型。连接、传输中断、响应解析等异常分别记录，不保存原始异常文本。页面默认折叠“最近调用”，不展示密钥、提示词、自定义请求头或额外参数。旧记录只显示当时已保存的字段。

HTTP 失败额外保留已知的服务端错误代码／类型、标准参数名和格式符合要求的请求编号；不记录可能回显密钥或提示词的原始错误消息。旧的仅有 HTTP 状态码的记录不能据此反推出具体原因。

## 存储与接口

渠道存入现有数据库的 `IMAGE_GENERATION_CONFIG_SECRET` 设置，聊天覆盖按数据库聊天 ID 存储。图片资产索引也存入现有数据库设置，快照默认位于 `data/image_generation/assets`，按聊天隔离；可通过 `IMAGE_GENERATION_ASSET_ROOT` 配置存储位置。快照不随旧任务临时目录的清理删除，默认目录纳入“生成内容”存储统计和包含生成内容的备份。迁移安装目录后按当前受控快照根目录和哈希解析资产；自定义外部快照目录需要一并迁移。复用现有数据库备份，无新增数据库迁移。密钥、所有自定义请求头和额外参数不通过管理 GET 接口回显；编辑留空保持原值，JSON `{}` 可清空高级字段。

- `GET /api/image-generation`：脱敏配置和官方模型目录。
- `PUT /api/image-generation`：带版本号原子保存，冲突返回 409。
- `POST /api/image-generation/{id}/test`：单渠道测试生成。
- `GET /api/image-generation/history`：脱敏调用记录。
- `POST /api/image-generation/models/discover`：使用当前表单或已保存连接获取模型目录；缓存按连接与凭据隔离。
- 聊天策略接口新增 `image_generation`，与其他聊天设置使用同一版本和事务。

测试通过 HTTP 模拟服务覆盖正常生成、编辑、流式结果、失败队列、凭据保护及入口集成；真实渠道可在配置后用“测试生图”检查。
