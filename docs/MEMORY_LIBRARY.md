# AI 助手记忆库

记忆库采用“原消息证据 → 事件记忆 / 人物观察 → 检索注入”的结构。Web 控制台只展示任务入口，不要求使用者理解数据库表或模型抽取参数。

## 聊天级设置

每个聊天只有三种模式：

| 模式 | 行为 | 适用情况 |
|---|---|---|
| 继承全局 | 使用 Chatbot 全局记忆策略，并自动跟随后续全局调整 | 默认及推荐 |
| 此聊天关闭 | 不检索已有记忆，也不生成新的记忆 | 敏感或无需记忆的聊天 |
| 此聊天自定义 | 开启记忆，仅覆盖复核、人物记忆、检索范围和召回条数等常用项 | 个别高流量或特殊聊天 |

“检索时间范围”只影响回答时回看多少天，不会删除数据库内容。抽取批次、向量模型、去重阈值和后台维护周期等低频参数仍统一放在全局设置中，避免同一含义出现多个开关。

## 记忆库工作台

工作台按操作任务分为六区：

- 概览：生效模式、待处理消息、向量检索状态、数据一致性和阶段摘要。
- 记忆：分页搜索事件卡，查看原消息来源，执行带原因的纠错或删除。
- 人物：分页查看人物摘要，按需读取事实、模式和观察证据；人工事实、别名和合并均写审计。
- 自动隔离：展示系统已经自动排除的事件与人物证据，不是人工任务列表；仅在发现误判时填写原因进行纠正。
- 变更记录：统一展示事件、阶段、人物身份、人物资料和维护记录；支持安全可撤销的变更会显示“撤销”。
- 数据维护：查看逻辑占用、Schema 版本和一致性检查，预览候选清理或分范围清理。

列表接口使用服务端分页；人物详情和原消息证据只在打开抽屉时读取，避免大群一次加载全部资料。

## 数据来源和写入规则

- 事件记忆保存来源游标和原消息引用；人工纠错会同步隔离由同一消息证据产生的人物观察及其投影。
- 人物证据账本是人物事实的唯一写入路径；旧人物摘要和旧结构化事实接口已经移除。升级前遗留的数据表本轮不会物理删除，但运行时不再读取或写入。
- 阶段摘要默认为自动维护。切换为“人工固定”后，后台不会覆盖；切回自动模式后由后续任务重建。
- 人工修改完成后，运行中的 Chatbot 会立即丢弃该聊天的旧检索缓存与锚定上下文，下一次回复读取新状态。

## 版本迁移与升级

记忆数据库使用 `memory_schema_meta` 按组件记录版本，目前包含 `core` 和 `person_memory`。应用启动时会先执行幂等迁移，再加载插件和开放 API；多个实例同时初始化同一文件时使用进程内路径锁和 SQLite 事务保护。

升级代码或依赖后无需手工刷新模型生成的记忆列表。数据库结构迁移由项目代码管理，不依赖 LiteLLM 的模型目录。启动日志中的 `Memory database schema ready` 会列出已生效组件版本。

## 生命周期、备份与清理

- `memory_retention_days`：检索窗口，`0` 表示不限；不删除正式记忆。
- `memory_candidate_retention_days`：已拒绝临时候选的保留天数，默认 90 天。
- `memory_maintenance_interval_hours`：后台候选维护检查间隔，默认 24 小时。
- `memory_automation_poll_minutes`：无人操作时扫描人物积压和待刷新投影的间隔，默认 15 分钟。

人物消息仍以 30 条为正常炼化门槛；低活跃人物积累至少 8 条相关消息并等待 14 天后会自动炼化。人物投影仍以 10 条新观察为正常刷新门槛，但只要已有未投影观察，最长等待 7 天。事件的 40 条核心消息加 12 条后文、阶段记忆的 40 张有效事件门槛均保持不变。

后台维护同时自动清理过期的已拒绝临时候选并运行引用一致性检查；异常会写入服务日志和记忆库健康状态，不会形成需要逐条人工审批的队列。

清理候选或正式记忆都要求输入完整聊天名称。正式清理前可在维护区创建 SQLite 在线备份；备份覆盖整个记忆数据库，写入 `data/memory_backups/`，并执行 `PRAGMA quick_check`。清理不会删除原始聊天日志，审计记录会保留并标记为 `cleared`，但已清理的记忆内容只能从数据库备份恢复。

不要直接复制正在运行的 `chat_memory.db` 文件作为备份；WAL 模式下单独复制主文件可能缺少尚未 checkpoint 的数据。

## 运维检查

分享或升级项目之前建议执行：

1. 在“数据维护”确认一致性为正常，并记录 `core`、`person_memory` 版本。
2. 检查自动隔离数量、人物处理延迟和待处理消息数量；自动隔离内容日常无需逐条处理。
3. 创建一次在线备份并确认 `quick_check` 为 `ok`。
4. 对测试聊天验证三种设置模式、事件纠错及撤销、人物事实编辑和移动端抽屉。
