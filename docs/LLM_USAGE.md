# 模型用量与计价

用量页按调用类型或聊天对象查看今天、7 天、30 天、本次运行及累计统计。中文名称来自核心与插件 `ui.llm_tasks`；英文标识保留第二行。群可下钻查看调用类型，详情展示用量、缓存、模型及逐次计价记录。

## 新统计周期

新账本不导入旧汇总。`llm_usage_v2.sqlite3` 使用独立 schema 2 账本，从空白开始；重启不重复清空。旧 `llm_usage.sqlite3` 不再使用，避免旧进程回写污染新统计。旧 `llm_stats.json`、`llm_daily_stats.json` 不再读取或写入。聊天、模型配置和调用历史不属于用量清理范围。内存中的运行健康与最近回复延迟仍供仪表盘使用，不作为费用来源。

## 记账口径

主表与顶部概览显示成功请求次数，失败尝试不计入该数字；失败数单列，明细保留总尝试次数。Token 和费用仍保留全部已上报消耗，包括失败请求已产生的用量。此次调整不删除历史失败明细。

- 每次请求保存一笔账，应用层重试、模型回退、空响应重试、流式补救及 Kimi 第二阶段分别记录。SDK 自动重试关闭，由记录请求的包装器执行配置的网络、429、5xx 重试；业务调用 ID 串联这些请求。
- 请求成功表示供应商返回成功；空内容后的再次请求仍会分别计入用量。失败但已上报的用量也计入；没有返回用量保持未知。
- Codex App Server 记录用量通知中的各模型请求，同一累计计数的重复通知只更新已有记录。只返回整轮用量的 CLI/第三方后端按整轮记账，详情标识“Codex 整轮用量”。不能观测的内部调用不捏造明细。整轮输入超过 272K 且无法确定各请求长度时，保留 Token，费用标为未知，避免误套长上下文价。
- 普通输入、缓存读取、缓存写入分别计价；推理 Token 为输出中的子集，不重复相加。原生 Gemini 的 thoughts 计入输出。优先采用供应商计数，本地 Token 估算保留标记。未上报显示 `—`，明确返回的零保留为零。
- 费用覆盖率为已计价请求数 / 请求总数，不能解释为账单准确率。没有供应商对账功能。

## 价格与币种

Codex 固定按实际返回模型的官方**标准 API Token 价格**折算，计入费用合计，标为“API 等值估算”。它衡量等值 API 消耗，不代表订阅扣款；工具、搜索、图片生成等单独收费项目未折算。当前官方快照覆盖 GPT-5.6 Sol/Terra/Luna、GPT-6 Astra/Sol/Luna；未知模型不映射为相近模型。

官方快照首次核验于 2026-09-07；GPT-6 Sol/Luna 价格补充核验于 2026-09-23：

- [OpenAI API 定价](https://developers.openai.com/api/docs/pricing)：包含缓存读写和 >272K 请求长上下文价格。直接 API 支持上报的 fast/priority、flex 档位；Codex 始终采用标准档位。
- [DeepSeek 官方定价](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)：V4 Flash/Pro/Vision，按北京时间工作日 9–12、14–18 高峰价格，其他时段为空闲价。

模型高级参数可声明按量、免费、订阅包含、暂不计价，以及币种和每百万 Token 的输入、输出、缓存读写单价。自定义单价按连接匹配；缺少实际用到的缓存单价时不猜测。Codex 的官方 API 等值政策优先于连接自定义值。连接名称含 Free 不自动视为免费。

普通 API 优先采用供应商明确返回的费用和币种（标为“供应商上报”，未对账），其次用连接配置、匹配官方端点的快照、可识别官方端点的 LiteLLM 目录估算。LiteLLM 的 `response_cost` 不当作实付金额。任意中转端点不能套用同名官方模型价，需要配置其实际价格。尚未支持的目录阶梯条件保持未知。

`app/services/llm_pricing.py` 是价格快照与标准化入口。更新价格须先核验官方来源、修改版本与规则，并运行计价测试；已有账目不重算。暂不联网自动刷新价格。

## 存储与查询

每笔账保留连接 ID、供应商/主机、实际模型、业务与请求 ID、原始数值用量、标准化用量、金额字符串、币种、来源、单价快照、版本和计价时间。不保存提示词、回复、API Key 或完整请求参数。

SQLite 事务原子写入请求明细及每日、累计、运行聚合；请求 ID 唯一，重复入账不重复累加。金额与单价使用 Decimal，存储十进制字符串；前端聚合接口输出数值用于展示。费用统一显示两位小数，累计时保留原始精度。每日聚合保留 31 天，请求账本与累计持续保存。日期按服务端时区统计。账本后续可按容量增加归档策略。

- `GET /api/llm/usage?period=today&view=chat`
- `GET /api/llm/usage?period=7d&view=task&subject=wechat:123`
- `GET /api/llm/usage/requests?period=7d&subject=wechat:123&task=assistant.chat&limit=20&offset=0`

请求明细的 `generation_timing` 保存客户端观测的 `first_token_seconds`（请求开始到首个可见文本块）、`last_token_seconds`、`generation_seconds` 和 `generation_tokens_per_second`。普通 API 默认内部流式接收后拼成完整响应；显式 `stream: false`、多候选和音频请求保留原调用方式，无法测得生成速度。供应商明确拒绝流式参数时可退回非流式。

页面保留简洁的 `首字 3.73s 速度(估算) 41 t/s`。首字单独记录请求开始至首个正文文本块的时间；速度采用供应商输出 Token 除以首个正文、推理或工具调用输出至模型消息完成的时间，不再使用本地分词，不扣除首块或推理 Token。

普通 API 在流结束时冻结完成时间；Codex 在对应供应商用量事件到达时冻结分段结束时间。Codex 若检测到分段跨越实际工具执行，则不显示该段速度，避免混入工具耗时。多段均有效时按输出 Token 总数除以各段时间总和汇总。缺少供应商用量、用量为估算、输出边界缺失、中断或计时不足 0.1 秒时显示 `—`。该下限只保护过短采样，并不能识别全部缓冲情况。

计时记录使用 `method=provider_output_over_decode_window`，保留 `first_output_seconds`、`generation_seconds`、`generation_tokens` 和 `token_count_source=provider_usage`，客户端速度仍标记 `estimated=true`。不会保存正文或改写供应商用量。旧记录缺少新的完成边界，保留首字时间，速度显示 `—`。旧 `output_tokens_per_second` 字段仅为兼容保留，不用于此展示。
